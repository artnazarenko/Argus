# Командный Git-процесс

## Роли

- Дизайнер работает с вариантами, состояниями, композициями и пояснениями
  Storybook.
- Разработчик проверяет API, доступность, токены и переносимость решения в
  production.
- Каждый участник может авторить изменения; обязательная точка синхронизации —
  pull request в `main`.

## Границы репозитория

В Git хранятся React/Vite/Storybook-исходники, нормализованные runtime-токены,
моковые данные, документация и lock-файл. Исходные Figma-файлы не хранятся в
репозитории: из них в проект попадают только нужные токены, названия вариантов,
иконки и зафиксированные решения.

## Рекомендуемая настройка удалённого репозитория

После создания пустого Git-репозитория владелец проекта один раз выполняет:

```bash
git remote add origin <URL-репозитория>
git push -u origin main
```

В настройках удалённого репозитория рекомендуется:

- запретить прямой push в `main`;
- требовать pull request и минимум одно ревью;
- требовать успешный job `storybook` из `.github/workflows/storybook.yml`;
- включить автоматическое удаление ветки после merge.

## Как передать работу коллеге

Коллега клонирует репозиторий, устанавливает зависимости по lock-файлу и
создаёт собственную ветку. Он может забрать незавершённую работу напрямую:

```bash
git fetch origin
git switch --track origin/feature/<short-name>
```

Для уже принятой работы достаточно обновить `main`. Важные решения не передаются
через zip-архив или копирование папок: история коммитов, pull request и CI
остаются единой точкой синхронизации.

## Конфликты

Если `main` ушёл вперёд, автор ветки обновляет её через `git rebase origin/main`,
решает конфликты в своей ветке, запускает `pnpm check` и делает force-push только
с безопасным флагом:

```bash
git push --force-with-lease
```

Нельзя переписывать `main` и нельзя использовать `git reset --hard` для решения
конфликтов без отдельного согласования.
